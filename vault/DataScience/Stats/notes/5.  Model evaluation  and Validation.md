# finding the goldilock zone

Overfitting and Under-fitting

Overfitting : if too much data is provided the model memorize the tranin data 1:1  and fail on the actual data 
- high training accuracy 
- low validation or testing accuracy
- poor generalization (a model's ability to perform accurately on **new, unseen data**) 

Under-fitting : if training data is too low it can't capture the pattern and  perform poor on test data
- low training accuracy 
- low validation or testing accuracy
- poor pattern capture

goldilocks :
- high training accuracy 
- high validation or testing accuracy
- good generalization 

## confusion matrix

it is the matrix of predictive values of model and actual values of the test data set

|                 | Predicted Positive  | Predicted Negative  | total |
| --------------- | ------------------- | ------------------- | ----- |
| Actual Positive | True Positive (TP)  | False Negative (FN) | -     |
| Actual Negative | False Positive (FP) | True Negative (TN)  | -     |
| total           | -                   | -                   | -     |

where :
- model prediction is represented as positive and negative 
- model prediction matched the actual value represented as true and if not false
	- model prediction == actual value : true (prediction was correct)
	- model prediction != actual value : False (prediction was wrong )
- ==_type 1 error_== : False Negative
- ==_type2 error_== :  False Positive

example:

|                 | Predicted Positive | Predicted Negative | total |
| --------------- | ------------------ | ------------------ | ----- |
| Actual Positive | 50 (TP)            | 10 (FN)            | 60    |
| Actual Negative | 5 (FP)             | 35 (TN)            | 40    |
| total           | 55                 | 45                 | 100   |

Metrics

| Metric      | Formula           | Question                                           |
| ----------- | ----------------- | -------------------------------------------------- |
| Precision   | TP / (TP + FP)    | When I predict Positive, am I right?               |
| Recall      | TP / (TP + FN)    | How many actual Positives did I catch?             |
| Specificity | TN / (TN + FP)    | How many actual Negatives did I catch?             |
| Accuracy    | (TP + TN) / Total | How many total predictions were correct?           |
| f1          | 2(PR)/(P+R)       | What is the balance between Precision and Recall?" |

## Accuracy
$$
\text{Accuracy}
=
\frac{TP + TN}
     {TP + TN + FP + FN}
$$
or $$
\text{Accuracy}
=
\frac{TP + TN}
     {Total}
$$
- basically total _true predictions_ divided by total tests  
- "Out of _everything_ the machine looked at, how many did it get right?"

## error rate 
$$
\text{Error Rate}
=
\frac{FP + FN}
     {TP + TN + FP + FN}
$$
or 

$$
\text{Error Rate}
=
\frac{FP + FN}
     {Total}
$$
- basically total _False predictions_ divided by total tests 

## precision 
$$
\text{Precision}
=
\frac{TP}
     {TP + FP}
$$
- "Out of ALL the times the machine guessed 'Positive' how many of them were true? ,  ignoring the negative predictions"
## Recall 
$$
\text{Recall}
=
\frac{TP}
     {TP + FN}
$$
-  FN =  actual positive predicted as negative 
- out of all the actual positive how many were wee able to predict correctly  
## Specificity
$$
\text{Specificity}
=
\frac{TN}
     {TN + FP}
$$
- **FP** = Actual Negative but Predicted Positive
- out of all actually negatives how many we predict correctly 

## F1 score

F1 Score combines **Precision** and **Recall** into a single number.

Formula:

$$
F1 = 2 \times \frac{\text{Precision} \times \text{Recall}}  
{\text{Precision} + \text{Recall}}  
$$

---

###### Why do we need it?

Suppose:

```text
Precision = 100%
Recall    = 10%
```

The model never makes false accusations, but misses 90% of the real positives.

Looks great on Precision.  
Terrible on Recall.

F1 says:

> "Let's balance both."

---

###### Intuition

|Metric|Question|
|---|---|
|Precision|When I say Positive, am I right?|
|Recall|How many real Positives did I catch?|
|F1 Score|How good is the balance between Precision and Recall?|

---

###### Example

```text
Precision = 0.8
Recall = 0.6
```

## 
$$
F1

\times\frac{0.8\times0.6}{0.8+0.6}
$$ 
$$ = 0.686  $$


F1 ≈ **68.6%**

---

###### When is F1 useful?

When classes are **imbalanced**.

Example:

```text
1000 patients
990 healthy
10 sick
```

A model that predicts:

```text
Everyone is healthy
```

gets:

```text
Accuracy = 99%
```

Looks amazing.

But it found **zero sick people**.

F1 exposes this problem because it considers both Precision and Recall.

---

###### Exam Answer

> **F1 Score** is the harmonic mean of Precision and Recall. It is used to evaluate classification models when both false positives and false negatives are important.

$$
F1 = 2 \times \frac{\text{Precision} \times \text{Recall}}  
{\text{Precision} + \text{Recall}}  
$$

###### Memory Trick

```text
Precision → Trust
Recall    → Coverage
F1 Score  → Balance between Trust and Coverage
```

If Precision and Recall are both high, F1 will also be high. If either one is poor, F1 drops quickly. That's why people often look at F1 instead of Accuracy alone.

|Situation|Metric|
|---|---|
|Balanced Classes|Accuracy often OK|
|Imbalanced Classes|Precision, Recall, F1|
|Missing positives is very costly (Cancer/Fraud)|Recall|
|False alarms are very costly|Precision|
|Need a balance of both|F1|
